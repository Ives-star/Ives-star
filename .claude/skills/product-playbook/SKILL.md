# Product Playbook

輸入：一個產品點子（例如 `/product-playbook 英文單字學習APP`）。

## 步驟 1：釐清問題

開始撰寫前，先一次提出以下 5 個問題，等使用者回答後再繼續：

1. 目標使用者：主要給誰用？（年齡層、身分、使用情境）
2. 核心差異化：相較既有競品，想靠什麼取勝？
3. 商業模式與規模：免費／內購／訂閱／買斷／B2B？預算與團隊規模？
4. 平台與技術範圍：iOS／Android／Web／跨平台？是否需要離線、帳號同步、後端？
5. 產出形式與深度：需要哪些章節、交付形式（文件或 repo 內 Markdown）？

若使用者已在訊息中回答部分問題，只問尚未回答的。

## 步驟 2：產出 Playbook

依回答撰寫以下章節，內容需具體、可執行，避免空泛形容詞：

1. **問題與機會**：要解決的痛點、市場規模或趨勢依據、為何是現在。
2. **目標使用者 persona**：2–3 個 persona，含背景、目標、痛點、使用情境。
3. **競品分析**：3–5 個主要競品，以表格比較功能、定價、優缺點，並指出差異化切入點。
4. **MVP 功能清單（含優先順序）**：以 Must / Should / Could / Won't（MoSCoW）分類，每項附一句理由。
5. **核心使用者流程**：從首次開啟到完成核心任務的步驟流程，可用條列或 Mermaid 流程圖。
6. **成功指標（KPI）**：北極星指標 + 3–5 個輔助指標，各附目標值與量測方式。
7. **上線時程與里程碑**：分階段（例如探索、MVP、Beta、正式上線），列出各階段產出與預估週數。
8. **風險與假設**：關鍵假設、驗證方式，主要風險與緩解措施。

## 撰寫原則

- 語氣客觀、務實，直接給建議，不加讚美或鼓勵性語句。
- 數據若為估計值須標明「估計」，並說明依據。
- 使用者未指定語言時，使用與使用者相同的語言撰寫。
